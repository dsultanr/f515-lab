VEGA CAN — запись для исследования запуска ДВС

Автомобиль: F515 / Evolute i-Space 4WD.
Начало сеанса: 2026-11-02T19:05:42.662+03:00. Завершение: 2026-11-02T19:12:00.743+03:00.
632580 CAN-кадров, 172 сочетания (шина, ID), три шины 0/1/2.
Исходный файл: 11800714 байт. CRC всех пакетов и SHA-256 копии проверены.

НАБЛЮДЕНИЕ ВЛАДЕЛЬЦА
По подтверждению владельца, при каждом Remote On запускался ДВС;
при Remote Off или открытии центрального замка ДВС глох.
Внутри интервала записи HA содержит 5 нажатий Remote On, 3 Remote Off,
3 unlock и 3 lock. Эти нажатия — временные ориентиры; число нажатий
не является независимым измерением числа физических запусков по RPM.
Исходный Remote On около 19:02:39 был до начала записи, но повторные
нажатия Remote On в 19:07–19:11 попали в интервал записи.
Remote On в 19:12:04 уже после окончания записи и помечен как внешний контекст.
Задача коллег: исследовать CAN-команды запуска ДВС для подзарядки ВВБ.
Работа ДВС подтверждена владельцем; положительный приток энергии в ВВБ
нужно проверять отдельно по знаку и масштабу тока/мощности.

ФАЙЛЫ
raw/stream.bin — неизменённые принятые USB-пакеты Vega, включая 0x1E и
ответы на управление приёмом. Авторизация выполнена до начала записи.
can/frames.csv — все кадры в порядке получения, seq начинается с 0.
Поля: tracker_ms (исходный 32-битный таймер трекера), relative_ms (от
первой метки CAN), bus_raw, can_id_hex, dlc, data_hex, storage_8_hex.
Последнее поле сохраняет все 8 байт хранения независимо от DLC.
can/candump.log — компактный candump, отсортированный по tracker_ms;
для равных меток сохранён исходный порядок. Время в секундах от первого
кадра, НЕ Unix time. can0/can1/can2 соответствуют исходным bus 0/1/2.
Назначение физических сегментов/ЭБУ этими именами не установлено.
can/id_summary.csv — количество кадров и диапазон времени по шине и ID.
can/gaps_over_100ms.csv — промежутки >100 мс между соседними полученными
метками всех шин; это наблюдаемые паузы, а не измерение потерянных кадров.
context/events.csv — HA-кнопки, DEBUG TX/ответы Vega и состояния зажигания.
context/ha_hv.csv — история изменений напряжения, тока и мощности ВВБ;
это события HA, не равномерная выборка и не синхронное измерение трёх величин.
Unavailable сохранено как отсутствие данных. Начальная строка истории
может быть восстановленным состоянием, а не новым измерением.
context/ha-history.json и ha-command-log.json — исходные выбранные поля
истории и журналов; идентификатор трекера и посторонние события исключены.
context/collector_checkpoints.csv — счётчики процесса записи примерно раз в 5 с.
convert.py — автономный декодер, Python 3.8+, без сторонних библиотек:
    python3 convert.py raw/stream.bin regenerated
manifest.json, context/verification.json, SHA256SUMS — метаданные и целостность.

ВРЕМЯ КОМАНД
Метка кнопки HA ставится перед вызовом интеграции. Remote On сначала
сбрасывает setting 1341 в 0, ждёт ответ и 1 секунду, затем ставит 1.
Во время этого сеанса от нажатия до DEBUG TX со значением 1 прошло
1,389–1,531 с. Remote Off и unlock не имеют этой фиксированной паузы.
В events.csv есть отдельные TX-метки из ~/ha/config/home-assistant.log;
это лог перед захватом сетевой блокировки/отправкой, НЕ аппаратное время CAN.
Vega setting 1341=0 перед Remote On — подготовительный сброс; его нельзя
считать отдельным нажатием Remote Off. Setting 1349=1 — lock, 1350=1 — unlock.
Vega-протокол из журнала HA и CAN-кадры из USB — разные уровни протокола.
ACK подтверждает принятие трекером, но не измеряет момент запуска ДВС.
Состояние ignition в HA может приходить позднее из телеметрии.

СОВМЕЩЕНИЕ ШКАЛ
CAN relative_ms отсчитывается от первого CAN-таймстампа. HA offset — от
начала сеанса на ГУ. Эти начала близки, но межчасовой сдвиг и задержка
USB/сети не калибровались. Сопоставление приблизительное; миллисекундную
точность между HA и CAN обещать нельзя. Таймер трекера не равен Unix time.
В CSV сохранены 3460 небольших возвратов метки назад в порядке
получения; candump отсортирован только для совместимости анализаторов.

ОГРАНИЧЕНИЯ ЗАПИСИ
Приём потока перевзводился 41 раз. Наблюдается 85 пауз >100 мс,
максимальная 2160 мс. Нулевая порча пакетов и dropped_bytes=0 не
означают, что весь трафик машины записан без пропусков. Короткая команда
может попасть в паузу. Не делать вывод «команды нет» только по отсутствию кадра.
Все сохранённые CAN ID <= 0x7FF и DLC=8. В candump ID представлены как
стандартные. Независимые признаки extended/RTR/TX/RX в исследованном
формате Vega не установлены; стандартный формат ID здесь — представление
для импорта, а не восстановленный флаг. CSV и BIN сохраняют исходные значения.
Расшифровки DBC и доказанной команды «запустить ДВС для зарядки» в пакете нет.

ФОРМАТЫ И ИМПОРТ
candump поддерживается SavvyCAN (CANDump/Kayak), а также инструментами
SocketCAN/can-utils. CSV подходит для pandas, таблиц и собственного анализа.
Для Vector ASC можно отдельно преобразовать локально через log2asc из can-utils.
