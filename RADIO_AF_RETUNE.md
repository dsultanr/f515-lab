# F515: радио само меняет частоту — причина в AF

4 ноября 2026 года штатное радио `com.seres.media.listen` дважды переключилось
с 96,0 на 98,7 МГц прямо во время прослушивания. Владелец подтвердил, что при
первом сбое не касался экрана и не нажимал кнопки на руле.

При повторе удалось записать прямое событие AF. Функцию отключили через
радиосервис и вернули выбранные 96,0 МГц. Отключение сохранилось в настройках.

## Как установили причину

Первое переключение произошло в 14:19:58 МСК. Новую частоту подтвердили экран,
настройки приложения и сохранённое состояние радиосервиса. ГУ и процессы радио
не перезапускались. AF был включён, дорожные объявления TA — выключены.

Одного включённого AF недостаточно для вывода о причине. Поэтому подключили
временный наблюдатель к службе `ts_radiomanager`. Он только получал уведомления
и не посылал команд настройки или переключения частоты.

Владелец вручную вернул 96,0 МГц в 14:31:49. При этом событие AF не пришло.
При следующем самостоятельном переходе, в **14:35:08.534 МСК**, наблюдатель получил:

```text
1793792108534 AF_CHANGE pastFreq=9600 newFreq=9870
1793792108534 radio_info index=0 radioType=0 pty=0 frequencyId=9870
```

Это прямое подтверждение автоматического переключения AF во втором эпизоде.
Первый эпизод согласуется с той же причиной, но отдельное событие AF тогда ещё
не записывалось. Почему радиосервис выбрал именно 98,7 МГц, отдельно не установлено.

## Что изменили

В 14:37 AF отключили, затем вернули 96,0 МГц. Проверка радиосервиса показала
`AF=false`; в `/data/vendor/dab/last_setting.dat` изменился только
`setting_af_link: true → false`. Остальные параметры радио сохранились.

AF отвечает за автоматическое переключение на альтернативную частоту.
После его отключения при ухудшении приёма подходящую частоту нужно выбирать вручную.

## Можно ли отключить через интерфейс

В проверенной версии штатного FM-интерфейса отдельного переключателя AF не нашли.
Кнопка **«Оповещение»** управляет дорожными объявлениями TA. Это подтверждается
обработчиком `OverseaLocalStationFragment.lambda$setProgramInfoListner$13`:
он меняет `getIsTrafficOn()` и отправляет уведомление об изменении дорожных объявлений.

В приложении также есть настройки связи DAB/FM. Их наличие не означает, что
в FM-интерфейсе доступен отдельный переключатель AF.

## Команды для проверенной версии прошивки

Нужен ADB-доступ с достаточными правами к службе `ts_radiomanager`.
Номера Binder-транзакций проверены по установленному `/system/framework/ts_radio_service.jar`:

```text
SHA-256: 51c672aad51ece4cd8433baf8eb7246ebe961f868c275626bc1615c64c4308d6
```

На другой версии прошивки соответствие методов и номеров транзакций нужно проверить
до выполнения команд. Хеш своего файла можно прочитать так:

```sh
adb shell -T 'sha256sum /system/framework/ts_radio_service.jar'
```

Проверить AF:

```sh
adb shell -T 'service call ts_radiomanager 30'
```

В ответе `00000000 00000001` означает, что AF включён;
`00000000 00000000` — выключен. Первое слово — отсутствие ошибки вызова.

Отключить AF и проверить результат:

```sh
adb shell -T 'service call ts_radiomanager 23 i32 0'
adb shell -T 'service call ts_radiomanager 30'
```

Включить AF обратно:

```sh
adb shell -T 'service call ts_radiomanager 23 i32 1'
adb shell -T 'service call ts_radiomanager 30'
```

Служба сама сохраняет настройку; редактировать системные файлы не требуется.
Эти команды не выбирают станцию — нужную частоту можно вернуть обычным способом.

## Материалы для разработчиков

- [Фрагменты записи](artifacts/radio-af-20261104/evidence.txt): ручное переключение,
  подтверждённый AF-переход и результат отключения.
- [Исходник временного наблюдателя](artifacts/radio-af-20261104/RadioWatch.java):
  регистрация слушателя, получение событий и ограниченное время работы без wake lock.

В проверенной службе native-сигнал149 вызывает `dealAfStatus()`, который передаёт
две частоты в `IRadioListener.onAfStatusChange` — транзакцию18 интерфейса
`com.ts.base.aidl.IRadioListener`. Полученное событие подтверждает AF-переход;
одно лишь отсутствие события ещё не доказывает, что AF не участвовал.

Наблюдатель предназначен для этой версии AIDL. Его можно собрать стандартными
`javac` и `d8` с Android 11 SDK в DEX JAR и запустить через `app_process`;
единственный аргумент — длительность от1 до3600 секунд. Для исправления запускать
наблюдатель не требуется.
